# Planly — продуктовые требования

## Цель

Создать личный календарный сервис с задачами, мероприятиями и днями рождения, отдельными аккаунтами и последующим голосовым созданием через Яндекс Алису. Текущий клиент работает в браузере с Linux, Windows, Android и других платформ без отдельного desktop-приложения; общий REST API в будущем сможет обслуживать нативные Android/iOS-клиенты.

## Текущая реализация и целевое направление

Реализованы задачи, календарь месяц/неделя/день, месячная доска с поиском, аутентификация и локальный контейнерный запуск. Поиск принят пользователем. Для мероприятий реализованы модель, хранение, service и полный HTTP CRUD; пользовательский интерфейс мероприятий реализован и принят пользователем после браузерной проверки. Для дней рождения реализованы backend и UI с CRUD, ежегодными появлениями и возрастом; backend и UI приняты пользователем. Базовые настройки профиля/календаря приняты. Фото и пять готовых аватаров реализованы и приняты пользователем 2026-10-23. Backend повторов Task/Event принят; На `codex/recurrence-simple` UI повторов упрощён до готовых вариантов и «Другое», backend расширен месячными и ежегодными правилами; пользовательская приёмка ожидается. Алиса и Web Push ещё не реализованы. Серверное развёртывание отложено по решению пользователя.

## Основной сценарий

Пользователь входит в Planly, открывает календарь на месяц, неделю или день, создаёт задачу с датой и временем и видит её в календаре. Изменения хранятся на сервере и доступны с других устройств после входа в аккаунт.

## MVP

1. Регистрация, вход и выход пользователя.
2. Разделение данных разных пользователей.
3. Создание, просмотр, редактирование и удаление задач.
4. Название задачи, необязательное описание, дата и, для timed-задач, время, статус выполнения.
5. Представления календаря: месяц, неделя и день.
6. Просмотр ближайших задач и создание задачи из интерфейса.
7. Адаптивный веб-интерфейс для ноутбука и телефона.
8. Перенос активных задач в календаре с доступной альтернативой drag-and-drop.

## Согласованные границы MVP

- В реализованном MVP календарная сущность — `Task`. Согласованное развитие добавляет самостоятельные `Event` и `Birthday`; существующие задачи и их API сохраняются.
- Каждая задача обязательно относится либо к точному моменту времени, либо к календарной дате на весь день.
- У задачи нет времени окончания; задачи без даты не входят в MVP.
- Завершение задачи хранится как время завершения и может быть отменено.
- При регистрации пользователь задаёт уникальный логин, email и пароль; для входа использует логин и пароль, а браузер получает серверную cookie-сессию.
- Владелец задачи определяется только по аутентифицированной сессии, а не по `user_id` из запроса.
- Часовая зона хранится в настройках пользователя в формате IANA, например `Europe/Moscow`.
- Клиент автоматически получает IANA-зону из API своей платформы при регистрации; если платформа не возвращает зону, используется `Europe/Moscow`. Пользователь не вводит и не подтверждает этот технический параметр.

Точные модели, HTTP-контракты и форматы ошибок описаны в [API.md](API.md).

## Согласованное функциональное развитие

Google Календарь служит ориентиром для различий типов записей, но синхронизация с Google не входит в ближайший объём.

| Тип | Первая версия | Развитие |
|---|---|---|
| Задача (`Task`) | Существующие название, описание, дата/время, выполнение, редактирование, перенос и поиск | Повторы, затем приоритеты и чек-листы |
| Мероприятие (`Event`) | Название, описание, начало и окончание, весь день, несколько дней, место и необязательная ссылка; без статуса выполнения | Повторы и напоминания |
| День рождения (`Birthday`) | Имя, день и месяц, необязательный год рождения, заметка; ежегодное отображение на весь день | Напоминания и поиск ближайших дат |

Для дня рождения возраст показывается только при известном годе. Исходная дата 29 февраля сохраняется, в невисокосные годы отображается 28 февраля. Изменение или удаление относится ко всей записи; исключений отдельных лет пока нет. Мероприятия первой версии личные: без гостей, приглашений, RSVP и автоматического создания видеовстреч.

### Интерфейс

- Навигация: «Календарь / Задачи / Мероприятия / Дни рождения / Настройки»; настройки также доступны через профиль. Используется согласованное тёмное оформление в стиле Kinetics; сохраняется адаптивность.
- Общий календарь объединяет типы с независимым включением/скрытием; тип различим по иконке и подписи, а не только по цвету.
- Кнопка `+` календаря предлагает тип записи; отдельный раздел открывает форму своего типа.
- «Задачи» сохраняют месячную доску, статусы и поиск. «Мероприятия» — месячный список по датам с поиском по названию, описанию и месту. «Дни рождения» — ближайшие даты на следующие 12 месяцев и поиск по имени.
- День рождения меняется через форму, а не перетаскиванием. Колонки выполнения применяются только к задачам.

### Настройки

Первая версия: отображаемое имя, загрузка/замена/удаление собственного фото или выбор одного из пяти предоставленных готовых аватаров, часовая зона, начало недели и формат времени 12/24. Фото расположено слева от имени пользователя; без фото показывается первая буква. Логин и email доступны для просмотра. Изменение учётных данных, подтверждение email и восстановление доступа — отдельное направление. Смена зоны сохраняет точные моменты; даты дней рождения и записей на весь день не сдвигаются.

### Голосовое создание и напоминания

Цель — создание всех трёх типов через навык Алисы в приложении Яндекса и на Станции, используя общую бизнес-логику Planly. Навык уточняет отсутствующие данные и неоднозначное время, зачитывает итог и сохраняет после подтверждения. Отмена ничего не создаёт; повторная доставка запроса не создаёт дубль. Ошибка не сопровождается ложным сообщением об успехе.

Связь аккаунта выполняется через OAuth 2.0. Голос на общей Станции не считается доказательством личности: до включения записи требуется проверка нескольких пользователей; при недоказанной идентичности запись блокируется. Фразы «Попроси Planly добавить задачу купить молоко завтра», «…запланировать встречу завтра с трёх до четырёх», «…запомнить день рождения Маши пятого мая» — целевые сценарии, а не обещание поддержки конкретного активационного имени.

Напоминания планируются отдельным этапом через Web Push после HTTPS-развёртывания, с настройками, серверной отправкой и подписками устройств. Поддержка зависит от браузера, ОС и разрешений. Голосовое озвучивание напоминаний Станцией в этот план не входит.

## Технологии

Go, PostgreSQL, REST API, React, TypeScript, Vite, Tailwind CSS, shadcn/ui, FullCalendar Standard v7, `temporal-polyfill`, Docker Compose.

## Этапы и резерв

Актуальная последовательность небольших инкрементов и их статусы находятся в [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md#функциональная-дорожная-карта). Дорожная карта согласована как направление; реализация, контракты, миграции и зависимости выполняются по одному инкременту после отдельного согласования.

В резерве: «Сегодня» и просроченные дела, приоритеты, чек-листы, личные списки/проекты, входящие без даты, поиск по всем задачам и сохранённые фильтры, отдельный крайний срок и длительность задач, дублирование и шаблоны, история и недельный обзор, импорт/экспорт, внешние календари. Совместная работа, привычки, Pomodoro, AI и нативные Android/iOS-клиенты не входят в ближайшую последовательность.
